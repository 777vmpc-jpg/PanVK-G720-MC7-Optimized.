## MediaTek swapchain behavior ported

A successful ARM64/API 29 source build was produced by GitHub Actions run
`45883375545` from port commit `feee979f60e5d8759ae1a51b6d886e617219a681`.
The resulting library is a new public-source build, not a byte-for-byte copy of
the Faux123 library. The original 1.1.9 package and metadata remain preserved as
the reference input.

The port reconstructs the narrow MediaTek linear-buffer behavior observed in
the 2026-11-26 display report from the MT6899 / Mali-G720 MC7 device:

- `vk_android_request_cpu_usable_swapchain_buffers()` is enabled during
  `panvk_physical_device_init_kbase()`.
- On Kbase architecture 5 or newer, the driver checks
  `ro.board.platform`; a `mt` prefix enables the MediaTek linear rule.
- The AHB image-format query adds
  `AHARDWAREBUFFER_USAGE_CPU_READ_RARELY | AHARDWAREBUFFER_USAGE_CPU_WRITE_RARELY`
  (`0x22`) to the base GPU framebuffer usage (`0x200`). For the observed
  format 37 / usage 0x11 combination, the expected query result is `0x222`.
- The Android gralloc usage query receives matching CPU read/write flags.
- If the ANB explicit-layout query returns `DRM_FORMAT_MOD_INVALID`, the
  guarded RGBA8888 color-target fallback can provide a linear modifier and a
  plane layout derived from pixel stride. The reported stride 2720 therefore
  yields a row pitch of 10880 bytes.
- The actual PanVK AHB WSI allocation descriptor remains `0x303` in the
  1.1.9 reference. The query value `0x222` must not be substituted for that
  allocation usage.

The build contains diagnostic strings for the AHB usage query and the
`gralloc fallback linear-forced` path. CI build success confirms compilation
and package generation only; it does not prove the fallback has executed on
this phone or that BOTWRecomp now renders correctly.

The test package prepared from this successful build uses the exact original
Faux123 1.1.9 `meta.json`, as requested. Its newly built library SHA-256 is
`d099eaad8fb99c9caedc30e4a514749857b57d0e15639b9d5eeed6da1f3fd003`.

## G720-specific candidate found

Reference repository: https://github.com/wonderkast02/panvk-g720-kbase-csf

- Pinned reference commit: `d9cbb91e5df720f0a62c4b5010d96c327aec315f`
- Its patch `0001-panvk-kbase-g720-register-count.patch` changes CSF register-count handling:
  - derives `cs_reg_count` from the CSF stream feature field instead of hard-coding 96;
  - supplies `nr_kernel_registers = MAX2(unpreserved_cs_reg_count, 4)` to the CS builder.
- This is a high-priority candidate because incorrect CS register limits can affect command-stream construction and GPU job execution. The public reference calls it G720-specific, but its published qualification is Mali-G720 MC8, not this phone's MC7.
- Do not apply it blindly: first verify the MediaTek Kbase CSF UAPI on this phone exposes the same `stream_features` encoding and that the patch applies cleanly to the exact Faux123 Mesa source state.

Reference validation notes for that repository describe native G720 MC8 testing. They are not evidence of MC7 validation and are not a Vulkan-conformance claim.

## Port order

1. Recover/obtain the exact Faux123 1.1.9 source patch stack. The public Faux123 tag contains documentation only; the 49 proprietary patches are not included. The binary cannot be safely decompiled back into maintainable Mesa source.
2. Pin Mesa `5a07217f034b3e50d8c7c7794f97a2df1742613b` and Kbase series `5b87b74`; do not silently substitute moving branches.
3. Check the G720 CS register-count patch against the pinned source and verify the MC7 kernel UAPI before porting.
4. Review G720 v12 CSF changes individually (queue lifecycle, tiler heap/OOM, memory/BO lifetime, texture formats and shader compiler). Keep architecture-scoped changes separate.
5. Build ARM64/API 29-compatible package, verify ELF/dependencies/metadata and run offscreen Vulkan tests before any BOTWRecomp test.
6. Test BOTWRecomp with logs and compare against the unmodified 1.1.9 package. FPS or rendering improvement is not claimed until measured.

## Current boundary

The recovered `.adpkg.zip` remains the immutable upstream reference. A
source-level test package has now been built successfully from the pinned Mesa
and public Kbase/CSF patch inputs, with the MediaTek swapchain behavior described
above reconstructed from the 1.1.9 binary. It is not byte-identical to Faux123
1.1.9 and does not recreate all 49 private patches. The package has not yet been
tested on the target MC7 phone. Keep the known-working driver available until
the new package has been installed and its BOTWRecomp logs confirm swapchain
creation, buffer import, and sustained rendering.
