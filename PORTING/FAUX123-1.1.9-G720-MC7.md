# Port plan — Faux123 1.1.9 / Mali-G720 MC7

## Decision

Use the same Mesa base commit named by Faux123 v1.1.9 (`5a07217f034b3e50d8c7c7794f97a2df1742613b`) and preserve the recovered Faux123 package and library as immutable reference artifacts. The exact Faux123 source tree cannot be reproduced from its public repository: the official README says its build contains 49 private patches and a private companion repository holds the build container, patches, test harnesses and recreate guide.

To continue without inventing provenance, the buildable public implementation will be reconstructed from the pinned Mesa base plus the public Android `mali_kbase` patch stack. This is a **source-compatible reconstruction around the same Mesa base**, not a claim that the resulting binary is byte-identical to Faux123 1.1.9 or contains all 49 private Faux123 patches.

## Public source inputs (pinned)

- Mesa: `5a07217f034b3e50d8c7c7794f97a2df1742613b`
- Kbase/CSF patch series: `zenithblue-oss/panvk-kbase-android@cf70e02b918e1864cbcd746a7fefa57b96c673ce`
- Kbase/CSF patch families: common, android, kbase-common, app-loader, wsi, csf, csf-v11 (through 233), jm-v9, jm-v7, then jm-v7-wip (through 0175).
- G720-specific reference: `wonderkast02/panvk-g720-kbase-csf@4082e6abb551b5cc81751c7d7fa2510d76b13fe0`
- Additional independent reference: `MineGraph-bilibili/panvk-Android@9e7214971a8839b8260654f650fd5712b486dc42`. This is an audit/reference input only; its files are not copied into the build until per-file license and provenance are checked.

The official Faux123 README and public source lock both identify the Mesa base commit above. The public Kbase repository pins that Mesa commit in `sources.lock`.

## Target evidence

The public v12 report records the exact same device model and hardware tuple:

- Xiaomi/POCO model `2412DPC0AG`
- MediaTek MT6899
- Mali-G720 MC7, GPU ID `0xc8700010`
- Android 16, Linux 6.6, Kbase/CSF
- PanProbe: 14/17 in six runs; Android swapchain lifecycle passed.
- Not yet demonstrated: real game execution, including BOTWRecomp.

This is strong architecture matching, but not proof that a driver build works on this user's individual firmware.

## Patch review order

1. **Build and identity:** reproduce pinned Mesa + Kbase/CSF series; verify AArch64 ELF, dependencies, Android API and package metadata.
2. **G720 MC7 bring-up:** preserve the v12 model/profile and CSF path; do not import MC8-only code as if it were MC7-tested.
3. **Tiler and queue lifetime:** review incremental tiler rendering (0161/0167/0174). Patch 0174 turns it on by default for v12 based on an SM-X926B workload test; retain a runtime opt-out and validate on MT6899 before making it unconditional.
4. **Known v12 functional gaps:** review patch 109 (viewport depth runs, depthBounds and shaderOutputViewportIndex). The v12 report explicitly says it was not run on v12 hardware; do not expose these features in a release until targeted tests pass.
5. **Textures:** audit BC decode/emulation and ETC2/EAC/BC6H/BC7 format paths; run raw decode, image sampling, copy/blit and BOTW texture-format tests. Passing `bc_decode` on the reference MC7 is encouraging, not enough to claim all game textures work.
6. **Memory/stability:** audit BO lifetime, heap growth, mapping limits, cache maintenance, AHB import and long-running command submission. Run stress tests before enabling aggressive optimizations.
7. **Game qualification:** PanProbe + PanPlay smoke first, then BOTWRecomp scene tests with Link visibility, environment textures, repeated scene transitions and long sessions.

## Explicit exclusions

- Build177 is not a source base.
- The recovered Faux123 1.1.9 binary is not patched in-place or presented as source.
- MC8-only tessellation/compiler changes are not bulk-copied.
- No performance improvement or game compatibility is claimed before device evidence.

## CI execution

The branch includes `.github/workflows/build-g720-mc7.yml`. It fetches the pinned public source stack, applies the patch series with strict no-fuzz/no-offset checks, compiles the Android ARM64 ICD with NDK r27.3, verifies the ELF architecture and packages a clearly marked test artifact. The workflow is intentionally not a release workflow; output is not declared device-tested.
