## Source availability finding

The official README states that the binary is built from Mesa commit `5a07217f`, the zenithblue `panvk-kbase-android` patch series release `v0.1.0-rc4`, plus 49 Faux123 patches. It also states that the build container, patches, test harnesses and recreate guide are in a **private companion repository**.

The recovered source archive contains the pinned public Mesa/Kbase inputs and the reconstructed public G720-v12 patch stack. It does **not** contain the private Faux123 overlay identified by the package metadata. Therefore it is a reproducible public reconstruction/reference tree, not proof of byte-exact recovery of the complete Faux123 v1.1.9 source.

The official package metadata lists Mali-G57, G77, G610 and G710. G720 MC7 is not listed as a validated target. GPU model strings inside a stripped library are not proof of functional support.

## G720-specific candidates and fixes

### 1. 64-bit provoking-vertex helper address — added to this repository

Reference: https://github.com/wonderkast02/panvk-g720-kbase-csf/issues/9#issuecomment-5977983155

The CSF provoking-vertex helper path computed the address of `fns_bo` into a `uint32_t`, then moved it into a 64-bit CS register. On kbase SAME_VA mappings, the GPU VA can be above 4 GiB; truncating it can make the CS prefetcher jump to an invalid address and cause a translation fault / queue timeout / DEVICE_LOST.

The candidate patch is stored at:

`patches/0002-fix-provoking-vertex-fn-address-truncation.patch`

It changes `fn_addr` to `uint64_t` and widens `fn_idx` before multiplying by the stride. The patch passed `git apply --check` against the recovered Mesa source tree at the pinned public Mesa base. The repository CI workflow now checks this patch against a clean checkout of commit `5a07217f034b3e50d8c7c7794f97a2df1742613b`.

**Hardware scope:** the upstream correction report describes testing on G720 MC8. This is strong architecture-level evidence but is not a test on the user's G720 MC7. Do not claim MC7 runtime validation until the driver is built and exercised on the target phone.

The upstream author explicitly corrected the earlier VT-lead / cross-subqueue-sync diagnosis and marked those earlier patches as superseded. Do not add those superseded changes as a substitute for the 64-bit address fix.

### 2. G720 CSF register-count patch

Reference repository: https://github.com/wonderkast02/panvk-g720-kbase-csf

The earlier candidate patch `0001-panvk-kbase-g720-register-count.patch` derives CS register limits from the CSF stream feature field rather than assuming a fixed count. It remains a separate candidate and is checked by the existing CI workflow. Confirm the exact MC7 UAPI/stream feature encoding before promoting it into a release build.

### 3. G720 v12 incremental tiler rendering

Reference: https://github.com/zenithblue-oss/panvk-kbase-android/blob/main/patches/jm-v7-wip/0174-panvk-csf-kbase-incremental-rendering-0161-on-by-def.patch

Patch 0174 enables `PANVK_KBASE_TILER_IR` by default for architecture v12. Its reported performance results are from an SM-X926B test device, not this Xiaomi / BOTWRecomp setup. Treat it as a candidate, not a guaranteed fix.

The G720 reference tree also contains later MC8-specific tessellation/compiler changes. Those are not to be copied wholesale into an MC7 build without checking the GPU architecture and source context.

## Port rules

1. Keep Faux123 1.1.9 as the reference baseline and retain its package/library identity only where the implementation is genuinely derived.
2. Do not use Build177 as the base.
3. Do not replace the base with a later MC8 tree.
4. Pin every source commit and patch revision; no moving branches in release builds.
5. Port v12 CSF/Kbase changes selectively, starting with queue/tiler lifecycle and memory correctness.
6. Audit texture-format paths (BC/ETC2/EAC), image layout, cache maintenance, AHB/WSI and shader compiler paths before enabling features.
7. Keep risky optimizations behind runtime debug options until they pass validation on the actual G720 MC7.
8. Never label a build as tested on the user's device until the user has run it and supplied logs/results.

## Validation gates before a test package

- Reproducible AArch64 Android build and package metadata validation.
- ELF dependency, SONAME, API and symbol checks.
- Vulkan loader/device creation without DEVICE_LOST.
- Offscreen tests: vertex/index/indirect draws, descriptor and pipeline lifetime, barriers, copies, fences, compute.
- Texture tests for formats used by BOTWRecomp; verify actual sampled pixels, not just successful image creation.
- On-screen rendering and swapchain/AHB presentation.
- Long-run memory and mapping stress; monitor for leaks and GPU hangs.
- BOTWRecomp scene validation: Link visible, environment textures correct, no missing geometry, sustained frame pacing.
