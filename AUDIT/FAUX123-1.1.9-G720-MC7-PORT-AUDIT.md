## Source availability finding

The official README states that the binary is built from Mesa commit `5a07217f`, the zenithblue `panvk-kbase-android` patch series release `v0.1.0-rc4`, plus 49 Faux123 patches. It also states that the build container, patches, test harnesses and recreate guide are in a **private companion repository**.

Consequently, the recovered release package is a binary reference, not a recoverable source tree. We must not claim that rebuilding the exact Faux123 1.1.9 source is possible from the public release repository alone.

The official package metadata lists Mali-G57, G77, G610 and G710. G720 MC7 is not listed as a validated target. GPU model strings inside a stripped library are not proof of functional support.

## Public source anchors

- Mesa pin from public `zenithblue-oss/panvk-kbase-android/sources.lock`: `5a07217f034b3e50d8c7c7794f97a2df1742613b`
- Public Kbase patch repository: https://github.com/zenithblue-oss/panvk-kbase-android
- Public G720 CSF reference repository: https://github.com/wonderkast02/panvk-g720-kbase-csf
- G720 v12 incremental tiler rendering patch 0174: https://github.com/zenithblue-oss/panvk-kbase-android/blob/main/patches/jm-v7-wip/0174-panvk-csf-kbase-incremental-rendering-0161-on-by-def.patch

Patch 0174 enables `PANVK_KBASE_TILER_IR` by default for architecture v12. Its reported performance results are from an SM-X926B test device, not this Xiaomi / BOTWRecomp setup. Treat it as a candidate, not a guaranteed fix.

The G720 reference tree also contains later MC8-specific tessellation/compiler changes. Those are not to be copied wholesale into an MC7 build without checking the GPU architecture and source context.

## Port rules

1. Keep Faux123 1.1.9 as the reference baseline and retain its package/library identity only where the implementation is genuinely derived.
2. Do not use Build177 as the base.
3. Do not replace the base with a later MC8 tree.
4. Pin every source commit and patch revision; no moving branches in release builds.
5. Port v12 CSF/Kbase changes selectively, starting with queue/tiler lifecycle and memory correctness.
6. Audit texture-format paths (BC/ETC2/EAC), image layout, cache maintenance, AHB/WSI and shader compiler paths before enabling features.
7. Keep risky optimizations behind runtime debug options until they pass validation on the actual G720 MC7.
8. Never label a build as tested on the user's device until the user has run it and supplied logs/results.

## Validation gates before a test package

- Reproducible AArch64 Android build and package metadata validation.
- ELF dependency, SONAME, API and symbol checks.
- Vulkan loader/device creation without DEVICE_LOST.
- Offscreen tests: vertex/index/indirect draws, descriptor and pipeline lifetime, barriers, copies, fences, compute.
- Texture tests for formats used by BOTWRecomp; verify actual sampled pixels, not just successful image creation.
- On-screen rendering and swapchain/AHB presentation.
- Long-run memory and mapping stress; monitor for leaks and GPU hangs.
- BOTWRecomp scene validation: Link visible, environment textures correct, no missing geometry, sustained frame pacing.
